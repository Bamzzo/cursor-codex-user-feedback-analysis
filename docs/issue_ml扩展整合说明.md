# Issue ML 扩展整合说明

## 定位

该包是 2026-11 新增的应用扩展，承接主项目已有的 RQ2 和 RQ3，不新增第五条平行研究线。主项目的一键流程只读取精简交付结果并核验；模型训练仍由 `issue_ml/` 的独立入口负责。

## 两项任务

| 任务 | 数据与方法 | 结果 | 可用场景 | 不能做什么 |
|---|---|---|---|---|
| bug / enhancement 分流 | 26,679 条去重 Issue；标题+正文 TF-IDF；逻辑回归；时间切分 21,343/5,287 | Accuracy 96.12%，Macro-F1 0.919，AUC 0.984，enhancement AP 0.942 | 人工 triage 候选分流、标签质检 | 不判断严重程度；维护者标签不等于真实故障真值 |
| completed 预测 | 24h 观察，预测 7d completed；结构与早期互动特征；Random Forest | 测试 n=1,395，正例 22；AUC 0.527，AP 0.100，Brier 0.021 | 研究早期信号、辅助排序诊断 | 不自动关闭、不承诺处理时间、不做自动分流 |

## 口径与验证

- 30 天早期互动对照 AUC 为 0.613，是对照实验，不是选模后的可部署指标。
- 结果已由 `src/12_validate_issue_ml_extension.py` 只读核验，输出为 `outputs/integrated/issue_ml_extension_validation.json`。
- 主流程默认执行到阶段 12；完整训练命令见 `issue_ml/提交说明.md`。
- 主线 RQ1–RQ4 的样本分母、图表和结论不因本扩展改变。

## 解释原则

“可分流”与“可预测完成”是两个不同问题。分类结果较好，主要说明文本中有足够线索复现既有标签；completed 预测较弱，主要受时间漂移、正例稀少和公开快照缺失影响。汇报时应把第一项放在 RQ2 的应用扩展，把第二项放在 RQ3 的研究性预测扩展，并同时展示限制。
