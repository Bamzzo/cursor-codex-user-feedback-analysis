# Cursor / Codex 用户反馈分析

本项目以 Cursor 和 OpenAI Codex 等 AI 编程智能体为研究对象，基于 Cursor 论坛、Codex GitHub Issues 及评论、Hacker News 等公开数据，分析用户关注点、问题组合、反馈处理过程与渠道差异。

项目按照“数据获取与质量核验 → 数据清洗与特征构造 → 探索性分析 → 主题与关联分析 → 生命周期分析 → 预测扩展 → 业务解释”的流程组织。主要方法包括 TF-IDF 与 NMF 主题模型、Apriori 关联规则、Kaplan–Meier 生存分析、Aalen–Johansen 竞争风险分析，以及带时间切分和 Purge Gap 的 TF-IDF + 逻辑回归文本分类。

## 项目内容

- `src/`：主分析流程和公共方法；`run_all.py` 为统一入口。
- `issue_ml/`：Issue 类型自动分流与处理结果预测扩展。
- `figures/`：最终分析图表。
- `outputs/`：机器可读的汇总结果和验收结果。
- `docs/`：综合报告、汇报稿、字段字典、口径说明和复现说明。

## 主要研究问题

1. 用户主要讨论哪些问题和主题？
2. 哪些 Issue 标签和问题模块经常共同出现？
3. Issue 的回复、关闭和长期积压情况如何？
4. 论坛与 GitHub Issues 反映出的反馈结构有何差异？
5. 文本信息能否辅助新 Issue 的初步分流和处理风险识别？

## 运行说明

公开仓库不包含完整原始数据集。若要复现主流程，请将六份公开数据文件放入 `data/raw/`，或通过环境变量 `FEEDBACK_RAW_DIR` 指定数据目录，再按 `docs/复现说明.md` 配置环境。项目结果和图表已经保留，便于直接查看研究产出。

```text
python src/run_all.py
```

## 主要结果

- NMF 主题分析识别出 MCP/网络、IDE 界面、云端协作和模型路由等核心讨论主题。
- Apriori 发现 Windows/桌面端、TUI/CLI、沙箱权限等标签组合，为问题分流和标签治理提供线索。
- 生存分析显示快速关闭与长期积压并存；`closed` 不等于 `fixed`，`completed` 也仅表示维护者标记的状态。
- Bug/Enhancement 文本分类可作为首轮分流辅助；处理周期和长期积压预测的文本信号较弱，不能替代业务决策。

## 数据与研究边界

数据来自公开社区，论坛正文覆盖不完整，GitHub 标签是维护者标注行为，不能直接等同于全部用户的真实故障率。项目仅用于课程研究与方法实践，结论应结合样本覆盖范围和各报告中的口径说明理解。
